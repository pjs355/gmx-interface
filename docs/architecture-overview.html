refactor-2 — Trade & SOR Architecture

Branch: refactor-2 · Repos: prinx-interface + predictions-api · May 2026
This document describes the refactor (module boundaries, unified quote/execute path, VACM, corridor prefund) — not a generic product overview.

1. Refactor goals

  • Fewer redundant calls — one SOR route poll; corridor-scoped RPC on execute (not all chains every time).
  • Trade box split — ~3k-line monolith → controller + hooks (~940 lines in PredictionMarketTradeBox.tsx).
  • Unified quoting — DFlow Pond overlay on POST /api/sor/route; deleted useDflowOrderQuote.ts and GET /api/dflow/order/quote.
  • VACM as single wallet map — accountWallets.ts; prefund reads chainsForBridgeCorridor() only.
  • Fail loud on missing wallets — partial via walletGate / isTradeFundingReady (not everywhere yet).

Prefund corridor (not “always Base”)

SOR planner sets leg.bridge.fromChain → toChain. Execute reads balances only for that corridor (chainsForBridgeCorridor). LiFi steps use allowedSourceChains: [bridge.fromChain] — one source chain per bridge group, chosen by the optimizer.

fromChainLiFi fromAddress (VACM)Notes
baseSCW or Limitless makerTwo Base pools; optional same-chain SCW→maker sweep before LiFi
polygonPolymarket deposit safeMay use Poly relay for signing
bnbEmbedded EOAUSDT on BSC
solanaSolana embeddedPrivy Solana sign

Cash already on the destination chain counts toward the prefund target first (computePrefundBridgeShortfallUsdHuman), reducing LiFi pull.

9. RPC networks vs wallets

JSON-RPC chains (Base, Polygon, BSC, Solana) are transport. VACM is who signs and where collateral sits. Limitless and LevelUp both use Base RPC but different wallets.
